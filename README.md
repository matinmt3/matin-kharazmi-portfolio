# محمد متین خوارزمی — طراحی و توسعهٔ وب

سایت شخصی فارسی و راست‌به‌چپ برای معرفی خدمات، نمایش نمونه‌کارها، مرور رزومه و شروع گفتگو دربارهٔ پروژه. «VisionGuard Pro» پروژهٔ شخصی محمد متین خوارزمی است؛ نسخهٔ نمونه‌کار، رابط فارسی نظارت تصویری را با داده‌های نمونه نمایش می‌دهد. سه نمونهٔ «آتلیه»، «مِتریک» و «لومن» پروژه‌های مفهومی هستند؛ دادهٔ داشبورد، محصولات و سبد فروشگاه نمایشی‌اند. این نسخه ادعای سابقهٔ مشتری، مدرک یا نتیجهٔ تجاری تأییدنشده ندارد.

## پنج صفحهٔ اصلی

خانه، نمونه‌کارها، خدمات، درباره و رزومه، و تماس صفحات مستقل با ناوبری مشترک هستند. پیش‌نمایش VisionGuard Pro، سه دمو، رزومهٔ چاپی و ویرایشگر هم در بسته قرار دارند؛ مجموعاً ۱۱ صفحهٔ HTML در بسته وجود دارد. روایت تصویری خانه با ScrollTrigger و حرکت خطوط کامل فارسی با GSAP ساخته شده است.

## اجرا و بررسی روی دستگاه

Node.js نسخهٔ ۲۰ یا بالاتر کافی است. کتابخانه‌ها و فونت همراه بسته هستند؛ اجرای سایت، بررسی و ساخت به نصب بسته‌های npm نیاز ندارند.

در پوشهٔ پروژه اجرا کنید:

```sh
npm start
```

سایت در `http://127.0.0.1:8749` باز می‌شود. برای امکانات ویرایش و خروجی ZIP از همین نشانی HTTP استفاده کنید؛ باز کردن مستقیم فایل با `file://` برای این امکانات مناسب نیست. سرور با `Ctrl+C` متوقف می‌شود.

```sh
npm run check
npm run build
```

بررسی، نحو JavaScript و JSON، فایل‌های فهرست انتشار، پیوندهای محلی HTML/CSS/راهنماها، ساختار داده و قراردادهای اعتبارسنجی نشانی را کنترل می‌کند. پیوندهای خارجی از نظر شکل نشانی بررسی می‌شوند؛ پاسخ سرویس مقصد یا ظاهر صفحه را آزمایش نمی‌کند. برای کنترل نهایی، پنج صفحهٔ اصلی، رزومه و پیوندهای پروژه‌های آن، ویرایشگر، پیش‌نمایش VisionGuard Pro و سه دمو را روی موبایل و دسکتاپ با صفحه‌کلید و گزینهٔ کاهش حرکت مرور کنید.

ساخت، فقط فایل‌های مشخص‌شده در [bundle-manifest.json](bundle-manifest.json) را به `dist/` کپی می‌کند و نسخهٔ ساخته‌شده را دوباره بررسی می‌کند. پوشهٔ `dist/` در هر ساخت جایگزین می‌شود؛ فایل اصلی خود را در آن ویرایش نکنید. `.git`، `node_modules` و خود `dist` وارد بسته نمی‌شوند. فایل جدیدی که باید منتشر شود، از جمله تصویر یا PDF، باید در فهرست manifest باشد. فایل عمومی [export-source.json](export-source.json) متن فایل‌های مخفی انتشار را نگه می‌دارد تا خروجی ZIP از سایت آنلاین هم کامل باشد؛ ساخت، این فایل را در `dist/` با متن فعلی بازسازی می‌کند.

## ویرایش محتوا و دریافت نسخهٔ قابل انتشار

پس از اجرای سرور، [studio.html](studio.html) را باز کنید. معرفی، اطلاعات تماس، نمونه‌کارها، تصاویر و فایل‌های PDF را ویرایش کنید؛ پیش‌نویس در IndexedDB همین مرورگر و همین نشانی ذخیره می‌شود. تغییرات ویرایشگر خودکار به GitHub یا کاربران دیگر ارسال نمی‌شود.

پیش‌نمایش [index.html?preview=draft](index.html?preview=draft) تغییرات محلی را نشان می‌دهد و هنگام رفتن به صفحه‌های اصلی دیگر، حالت پیش‌نمایش حفظ می‌شود. صفحهٔ عادی، دادهٔ منتشرشدهٔ [data/site-data.js](data/site-data.js) را می‌خواند. پیش‌نویس با تعویض مرورگر، تغییر نشانی/پورت یا پاک کردن دادهٔ سایت منتقل نمی‌شود؛ پیش از این کارها خروجی ZIP بگیرید.

خروجی ویرایشگر یک بستهٔ کامل سایت است: فایل‌های اصلی، دادهٔ به‌روز، تصاویر/PDFهای بارگذاری‌شده و `bundle-manifest.json`. ZIP را خارج از پوشهٔ فعلی باز کنید، نسخهٔ استخراج‌شده را بررسی کنید و سپس فایل‌های آن را جایگزین نسخهٔ مخزن کنید. صرف دریافت ZIP، سایت آنلاین را تغییر نمی‌دهد. جزئیات مدیریت محتوا و فایل‌ها در [راهنمای محتوا](docs/CONTENT-GUIDE.md) آمده است.

ویرایشگر یک ابزار محلی است و صفحهٔ ورود یا دسترسی مدیریتی به سرور ندارد. از اطلاعات محرمانه در رزومه، شرح پروژه و فایل‌هایی که قصد انتشار عمومی آن‌ها را دارید استفاده نکنید. فرم همکاری پیش‌نویس ایمیل آماده می‌کند یا شرح پروژه را کپی می‌کند؛ ارسال ایمیل در برنامهٔ ایمیل کاربر انجام می‌شود.

## انتشار در GitHub Pages

مخزن عمومی این پروژه `matinmt3/matin-kharazmi-portfolio` است. فایل‌های پروژه باید در ریشهٔ مخزن باشند، نه داخل یک پوشهٔ اضافی پس از استخراج ZIP.

1. در تنظیمات مخزن، **Settings → Pages → Build and deployment → Source** را روی **GitHub Actions** قرار دهید.
2. نسخهٔ بررسی‌شده را روی شاخهٔ `main` ثبت و push کنید.
3. در بخش **Actions**، اجرای **Check and publish portfolio** را دنبال کنید. انتشار پس از موفقیت ساخت انجام می‌شود؛ اجرای pull request فقط ساخت را بررسی می‌کند.
4. سایت را در [matinmt3.github.io/matin-kharazmi-portfolio](https://matinmt3.github.io/matin-kharazmi-portfolio/) بررسی کنید. برای اجرای دوباره، در همان workflow از **Run workflow** روی `main` استفاده کنید.

فایل [deploy.yml](.github/workflows/deploy.yml) مطابق [راهنمای رسمی workflowهای Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages) از `checkout@v6`، `configure-pages@v5`، `upload-pages-artifact@v4` و `deploy-pages@v4` استفاده می‌کند؛ Node.js ۲۴ با `setup-node@v6` آماده می‌شود. مجوزهای انتشار فقط به job انتشار داده شده‌اند. این انتخاب‌ها در ۶ اکتبر ۲۰۲۶ با مستندات رسمی بررسی شده‌اند.
